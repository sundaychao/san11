# 错列方格战斗系统设计规格

状态：已通过对话确认，等待书面复核  
日期：2026-07-15

## 1. 产品目标

在现有“建安十三年：荆襄争夺”经营游戏中加入直接发生在大地图上的回合制战棋系统。视觉采用原创的写实水墨 2.5D 沙盘地形，规则参考经典三国历史策略游戏的大地图作战体验，但不复制任何现成游戏的地图、建筑、角色、界面或文本素材。

第一阶段只实现一种基础部队，形成完整闭环：城市出征、错列方格移动、普通攻击、反击、地形修正、攻城、占领、断粮、AI 作战、统一胜利与灭亡失败。后续兵种、战法和军事建筑不得成为本阶段的前置依赖。

## 2. 已确认范围

### 2.1 包含

- 原创写实水墨 2.5D 荆襄战场底图
- 约 `36×22` 的错列方格逻辑地图
- 每支部队占据一个格子，同一格不能叠加部队
- 每座城市完整占据 7 格：中心格加六方向相邻格，七格均不可进入
- 六方向对称移动与 A* 寻路
- 单一基础部队、出征、移动、待命、攻击、反击和攻城
- 平地、道路、森林、丘陵、高山、深水六类地形
- 每月上旬、中旬、下旬的旬制回合
- 与玩家共用规则的 AI 出征、移动和攻击
- 统一、灭亡和 24 个月国力结算三类结束条件
- `schemaVersion: 1` 存档向 `schemaVersion: 2` 的迁移
- 桌面与手机的 Canvas 地图交互

### 2.2 不包含

- 枪、戟、弩、骑兵和攻城器械等兵种差异
- 战法、计略、火攻、陷阱、阵、箭塔和军事设施
- 水军、船只、水面移动和水战
- 单挑、舌战、俘虏处置和武将死亡
- 联盟、外交、援军和多人联机
- 可旋转的真 3D 镜头与实时 3D 模型

## 3. 地图视觉与渲染

地图采用高斜俯视角的 2.5D 沙盘构图。地貌必须清晰表现立体山脉、河谷、森林、道路、田地、村落、城池、桥梁与雾化远景。色彩以冷灰绿、石青、墨黑和低饱和土色为主，保证地形在网格下仍可辨认。

底图是预渲染位图，Canvas 在世界坐标中实时绘制。默认桌面网格目标尺寸为原 64px 概念格的约 `2/3`，即 `42–44px`；手机端可通过缩放保持触控目标不低于 `34px`。网格线必须低对比，避免遮挡地图地貌。

- 普通方格线：低对比灰白色
- 可移动范围：淡金色半透明填充
- 攻击目标：暗红色半透明填充
- 预览路径：金色折线与方向点
- 选中部队：势力色描边和轻微光晕
- 不可通行格：不额外涂黑，依靠高山和深水地貌表达；悬停时显示阻挡标记

Canvas 负责底图、网格、地形状态、部队、城市占地、路径和战斗效果。React DOM 负责顶部日期栏、部队详情、城市详情、命令菜单、确认窗口和战报。地图缩放、拖动和命中检测共享同一套世界坐标变换，不能分别维护偏移量。

## 4. 错列方格坐标

使用零起始列 `q` 和行 `r`。偶数列在视觉上向上移动半格：

```text
pixelX = q * cellWidth
pixelY = r * cellHeight + (q % 2 === 0 ? -cellHeight / 2 : 0)
```

每个格子只有六个共享完整或半条边的对称邻格。

偶数列 `q` 的邻格：

```text
(q, r - 1), (q, r + 1),
(q - 1, r - 1), (q - 1, r),
(q + 1, r - 1), (q + 1, r)
```

奇数列 `q` 的邻格：

```text
(q, r - 1), (q, r + 1),
(q - 1, r), (q - 1, r + 1),
(q + 1, r), (q + 1, r + 1)
```

所有邻接必须满足双向对称。所谓“七个行动选择”指六个移动方向加原地待命，不存在第七个移动邻格。

命中检测先根据世界坐标求列，再减去该列的半格偏移求行。地图边界外的坐标永远无效。格子标识统一使用字符串 `${q},${r}`，存档中不保存像素坐标。

## 5. 地形与移动

| 地形 | 移动消耗 | 防御倍率 | 可通行 |
| --- | ---: | ---: | --- |
| 道路 | 1 | 1.00 | 是 |
| 平地 | 1 | 1.00 | 是 |
| 森林 | 2 | 0.85 | 是 |
| 丘陵 | 2 | 0.80 | 是 |
| 高山 | - | - | 否 |
| 深水 | - | - | 否 |

防御倍率作用于守方所受伤害，数值越低表示减伤越强。城市七格占地、地图边界外格和任何部队当前占用格均不可作为移动终点。友军与敌军都阻挡寻路，不允许穿过。

基础部队每旬有 `5` 点移动力。A* 的路径成本等于进入格的移动消耗；超过剩余移动力的路径不可提交。若多条路径成本相同，按邻格列表顺序和格子键排序保证结果确定。

## 6. 数据模型

`GameState` 升级到 `schemaVersion: 2`，增加：

```ts
type TenDay = 1 | 2 | 3;
type TerrainType = 'road' | 'plain' | 'forest' | 'hill' | 'mountain' | 'deepWater';

interface GridCell {
  q: number;
  r: number;
  terrain: TerrainType;
}

interface ArmyUnit {
  id: string;
  forceId: ForceId;
  leaderId: string;
  homeCityId: CityId;
  q: number;
  r: number;
  troops: number;
  food: number;
  energy: number;
  movementRemaining: number;
  moved: boolean;
  acted: boolean;
}
```

`GameState` 增加 `tenDay`、`turnForceId`、`grid` 和 `units`。`City` 增加 `durability`、`maxDurability`、`gridQ` 和 `gridR`，其中坐标指向城市七格占地的中心格。`Officer` 的位置改为判别联合：驻城、出征或在野，避免同一武将同时存在于城市和部队。

```ts
type OfficerLocation =
  | { kind: 'city'; cityId: CityId }
  | { kind: 'unit'; unitId: string }
  | { kind: 'unaffiliated'; cityId: CityId };
```

城市允许 `governorId: string | null`。无太守城市不能执行内政，第一名通过调动进入该城的己方驻城武将自动成为太守。

## 7. 出征

“出征”是新的城市命令。提交时选择一名未行动的驻城武将、`1000–10000` 兵力和携带粮草。携带数值不得超过城市库存，城市至少保留 `500` 兵力。

出征消耗势力行动力 `20`。成功后兵力和粮草立即从城市扣除，武将位置改为部队，部队生成在城市七格占地外围中距离目标最近的合法格。若没有合法出生格，命令失败且不消耗任何资源。

新部队初始气力 `100`、移动力 `5`，但创建当旬视为已经移动、尚未攻击；它可以原地攻击相邻敌军或城市，也可以待命，不能在出征当旬继续移动。

## 8. 旬制与势力回合

每月分为上旬、中旬、下旬，共 `72` 旬。玩家势力先行动，其余三个势力按场景固定顺序行动。一个势力回合内可交错执行内政与任意己方部队行动。

玩家点击“结束本旬”后：

1. 当前玩家所有未行动部队自动待命。
2. 三个 AI 势力依次执行内政、出征和部队行动。
3. 所有部队结算粮草、断粮和状态。
4. 日期从上旬推进到中旬、中旬推进到下旬；下旬结束后执行月末城市结算并进入下月上旬。
5. 检查统一、灭亡或第 24 个月结束条件。
6. 所有存活部队恢复 `movementRemaining = 5`、`moved = false`、`acted = false`。

城市收入、人口增长和随机事件只在下旬结束时结算。势力行动力仍按月恢复为 `80`，不会每旬恢复。驻城武将的内政行动状态在新月上旬恢复。

## 9. 部队行动状态机

部队每旬有以下合法流程：

```text
未行动 -> 选择移动范围 -> 预览路径 -> 确认移动 -> 可攻击/待命
未行动 -> 原地攻击 -> 已行动
未行动 -> 待命 -> 已行动
移动后 -> 攻击 -> 已行动
移动后 -> 待命 -> 已行动
```

攻击后不能移动或再次攻击。取消路径预览不改变状态；移动一旦确认不能撤销。操作失败不得改变部队、资源、随机游标或日志。

## 10. 普通攻击与反击

普通攻击只能选择六方向相邻的一支敌军。攻击伤害使用纯函数计算，并通过现有种子随机数推进波动：

```text
attackScore = troops × (0.08 + leadership / 2000 + war / 3000)
rawDamage = 240 + attackScore
terrainModifier = defender 所在地形的防御倍率
randomModifier = 0.92 + seededRandom × 0.16
damage = clamp(round(rawDamage × terrainModifier × randomModifier), 120, 2200)
```

实际伤害不得超过守方当前兵力。守方在受击后仍有兵力、与攻击者相邻且本次不是反击时，立即进行一次反击：使用同一公式，但最终伤害乘以 `0.6`。反击不会改变守方本旬行动状态。

每次主动攻击消耗气力 `10`。气力不足 `10` 时不能攻击。每旬结算时，有粮部队恢复 `5` 气力，上限 `100`。

## 11. 攻城与占领

城市完整占据以 `(gridQ, gridR)` 为中心的 7 格：中心格加六方向相邻格。城市建筑方向必须与错列方格方向平行，不能斜着摆放。攻击者位于任一城市占地格的六方向外围邻格时可以攻城。

攻城先按普通攻击公式计算 `damage`，然后：

```text
garrisonDamage = round(damage × 0.65)
durabilityDamage = round(damage × 0.45)
```

城市守军和耐久分别扣减，最低为 0。城市不会反击。守军或耐久任一降到 0 时城市被占领：

- 城市归攻击方，治安降低 `20`，最低为 0。
- 资金和粮草保留一半，向下取整。
- 原太守和驻城武将撤退到最近的原势力城市；若原势力已无城市则变为在野。
- `governorId` 设为 `null`。
- 攻击部队仍停留在外围格，不自动进入城市。
- 城市守军设为 `min(1000, floor(attacker.troops × 0.2))`，并从攻击部队扣除相同兵力。
- 城市耐久恢复为 `ceil(maxDurability × 0.2)`。

若占领后攻击部队因移交守军而兵力低于 `1`，保留 `1` 兵，城市守军相应减少，避免占领动作同时消灭攻击者。

## 12. 部队消灭与粮草

部队兵力降到 0 时立即从地图移除。主将撤退到距离原部队位置最近的己方城市，并在下一旬可用；没有己方城市时变为在野。部队剩余粮草消失。

每旬每支部队消耗：

```text
foodCost = max(100, ceil(troops / 20))
```

粮草足够时正常扣除。粮草不足时归零，并执行：气力减少 `20`，兵力减少 `max(100, ceil(troops × 0.08))`。断粮逃兵导致兵力归零时按部队消灭处理。

## 13. AI

AI 使用与玩家相同的验证和执行函数，不获得额外移动力、兵力、粮草或地图信息。

每个 AI 势力回合按以下顺序：

1. 若边境城市守军低于 `3000`，优先征兵。
2. 若城市兵力至少 `6000`、粮草至少 `8000` 且存在可用武将，向最近敌城出征 `4000` 兵和 `6000` 粮。
3. 每支部队寻找路径成本最低的敌方城市。
4. 若当前可攻击敌军，优先攻击兵力最低者。
5. 若可攻城，攻击城市。
6. 否则沿 A* 路径移动不超过剩余移动力，并在移动后再次检查攻击目标。
7. 无合法动作时待命。

同成本目标按城市 ID、部队 ID 排序。所有随机选择必须推进 `rngCursor`，保证读档后行为可复现。

## 14. 胜负与评分

- 任一势力占领全部 8 座城市时立即统一胜利。
- 玩家失去全部城市时立即失败，即使地图上仍有玩家部队。
- 第 24 个月下旬结算后仍未统一，使用现有国力排名结算。

国力评分继续计算城市与武将，并增加部队兵力：每支部队的兵力计入所属势力总兵力，避免出征导致评分凭空下降。

## 15. 存档迁移

存档键保持不变，内容升级为 `schemaVersion: 2`。读取版本 1 时执行一次纯函数迁移：

- `month` 保持原值，`tenDay = 1`。
- `turnForceId = playerForceId`。
- 根据固定场景数据创建 `grid`。
- `units = {}`。
- 城市补入固定坐标、`maxDurability` 和满耐久。
- 武将位置根据原 `forceId` 与 `cityId` 转为驻城或在野。
- 旧版 `acted` 保持，直到下一个月上旬恢复。

迁移后必须通过版本 2 完整校验才可写回。损坏数据不部分迁移，也不覆盖原存档。

## 16. 错误处理

规则引擎对以下情况返回可读错误且保持原状态不变：

- 出征兵力、粮草、武将或出生格不合法
- 目标格越界、不可通行、被占用或超过移动力
- 路径不连续或包含非六方向邻格
- 已行动部队再次移动或攻击
- 攻击目标非敌方、距离错误或气力不足
- 城市目标不在七格城市占地外围邻接范围
- 当前不是玩家势力回合
- 游戏已经统一、灭亡或结算结束

Canvas 加载失败时显示可恢复错误面板，保留重新加载和返回标题入口。底图未加载完成前不接受地图点击。

## 17. 测试与验收

单元测试必须覆盖：

- 偶数列与奇数列的六方向邻格及双向对称
- 格子与像素坐标互转、边界和半格命中
- 七格城市占地与外围邻格
- A* 地形成本、占用阻挡、同成本确定性
- 出征资源扣除、出生格选择和失败原子性
- 移动、待命、先移动后攻击和禁止攻击后移动
- 攻击公式、地形减伤、反击、气力和部队消灭
- 攻城、占领、武将撤退、守军转移和胜负检查
- 粮草消耗、断粮、逃兵和旬/月日期推进
- AI 始终生成合法动作且结果可复现
- 版本 1 迁移、版本 2 读写和损坏存档拒绝

集成测试必须覆盖：玩家出征、移动、攻击敌军、攻占一城、结束旬、AI 反击、刷新读档并继续，以及统一和灭亡两种结局。

浏览器验收视口为 `1440×900`、`1920×1080` 和 `390×844`。必须检查：

- 底图非空且与错列方格稳定对齐
- 缩放和拖动后命中格正确
- 部队严格单格占用且不重叠
- 七格城市占地清晰，建筑方向与格子方向平行
- 移动、路径、攻击和目标颜色可区分
- 手机上最小可点击目标不低于 `34px`
- 面板不遮挡当前部队、目标城市和确认按钮
- 完整攻城流程无控制台错误

## 18. 实现边界

新增模块应按职责拆分：

- `grid`：坐标、邻接、命中与地形
- `pathfinding`：可达范围与 A*
- `battle`：出征、移动、攻击、反击、攻城与粮草
- `battle-ai`：目标评估与合法动作选择
- `turn`：旬制与势力轮转
- `persistence`：版本 2 校验与版本 1 迁移
- `BattleMap`：Canvas 渲染与指针交互
- `UnitPanel`、`DeployDialog`、`BattleCommandMenu`：React 操作界面

规则模块不得依赖 React、Canvas 或浏览器存储 API。任何 UI 动画都只能表现已经由规则引擎提交的结果，不能反向决定伤害、路径或占领结果。
